# GIS 地理信息管理平台项目说明

## 1. 项目概述

本项目是一个前后端分离的 GIS 地理信息管理平台，核心目标是实现用户空间数据的上传、管理、发布、地图可视化以及基础空间分析。

项目整体由两个子工程组成：

- `vuePrj`：前端可视化与交互系统
- `expreePrj`：后端接口、数据管理、GeoServer 发布与分析任务调度

平台以 Cesium 三维场景为核心展示窗口，结合 GeoServer 提供 WMS 服务，并通过 Python 脚本完成部分空间分析处理。

## 2. 使用到的主要技术

### 2.1 前端技术

- `Vue 3`
  用于构建前端单页应用。
- `TypeScript`
  用于提升前端代码的类型安全与可维护性。
- `Vite`
  作为前端开发与构建工具。
- `Vue Router`
  负责登录页、工作台、个人中心、设置页等路由管理。
- `Element Plus`
  用于表单、弹窗、表格、树组件、消息提示等 UI 交互。
- `Axios`
  用于封装前端与后端的 HTTP 请求。
- `Cesium`
  用于三维地球场景展示、影像图层加载和空间数据可视化。
- `vite-plugin-cesium`
  用于在 Vite 项目中集成 Cesium 资源与 Worker。
- `JSZip`
  用于前端将多文件 Shapefile 打包为 ZIP 后上传。

### 2.2 后端技术

- `Node.js`
  作为后端运行环境。
- `Express 5`
  用于搭建 REST API 服务。
- `TypeScript`
  用于后端接口、控制器、服务模块的开发。
- `Multer`
  用于头像、空间数据文件上传处理。
- `JWT + jsonwebtoken`
  用于用户身份认证与接口鉴权。
- `bcryptjs`
  用于密码加密与校验。
- `CORS`
  处理前后端跨域访问。
- `dotenv`
  用于读取环境变量配置。

### 2.3 数据与 GIS 相关技术

- `MongoDB + Mongoose`
  用于存储用户信息、数据资产信息等业务数据。
- `PostgreSQL + Knex`
  用于存储 GeoJSON 要素数据，并支持空间 SQL 视图方式发布。
- `GeoServer`
  用于发布栅格和矢量图层，向前端提供 WMS 服务。
- `geoserver-node-client`
  用于后端自动创建工作区、数据存储和发布图层。
- `Python`
  用于执行 GIS 分析脚本。
- `GDAL / Python 地理处理脚本`
  用于坡度坡向、等高线、缓冲区、山体阴影、DEM 转地形等分析与转换任务。

## 3. 已实现的功能

### 3.1 用户与权限功能

- 用户注册
  支持账号、密码、确认密码校验，并支持上传头像。
- 用户登录
  登录成功后签发 JWT，并在前端持久化保存。
- 路由鉴权
  未登录用户无法访问工作台、个人中心、设置页。
- 个人中心
  支持查看个人资料、头像、角色、创建时间、数据数量、存储占用等信息。
- 个人资料修改
  支持修改昵称、头像和密码。

### 3.2 数据管理功能

- 用户空间数据上传
  支持上传矢量和栅格数据。
- 支持的主要数据格式
  包括 `GeoJSON / JSON / SHP(多文件打包 ZIP) / TIFF / TIF`。
- Shapefile 文件完整性检查
  前端会检查 `.shp` 是否配套 `.shx` 和 `.dbf`，并提示缺失情况。
- 我的数据列表
  在个人中心中展示用户上传的数据，支持按矢量、栅格筛选。
- 数据删除
  支持删除用户自己的数据资产及其关联记录。

### 3.3 数据发布与地图展示

- 工作台三维地图展示
  基于 Cesium 初始化三维地球场景，并加载基础底图。
- 我的数据拖拽上图
  用户可将左侧资源面板中的数据拖入地图区域。
- 自动发布到 GeoServer
  后端根据数据类型自动完成发布流程：
  - `TIFF` 发布为 CoverageStore
  - `GeoJSON` 写入数据库后通过 SQL 视图发布
  - `SHP ZIP` 解压后发布为 DataStore
- WMS 图层加载
  前端通过 `Cesium.WebMapServiceImageryProvider` 将发布结果加载到地图中。
- 图层管理
  支持图层可见性切换、图层顺序拖拽调整。
- 资源清理
  页面卸载或关闭时，会向后端发送清理请求，删除临时发布资源。

### 3.4 空间分析功能

当前真正打通前后端和后端处理链路的工具包括：

- 缓冲区分析
  基于矢量数据执行缓冲区生成，输出结果发布为 GeoServer 图层并回显到地图。
- 坡度分析
  基于栅格 DEM 数据生成坡度结果图层。
- 坡向分析
  基于栅格 DEM 数据生成坡向结果图层。
- 等高线提取
  基于栅格 DEM 提取等高线，输出矢量结果并加载到地图中。
- 山体阴影分析
  基于栅格 DEM 生成 hillshade 栅格结果。

### 3.5 地形相关能力

- DEM 转地形数据
  后端已具备 `demToTerrain.py` 地形生成能力，可将 DEM 转换为 terrain 数据目录。
- 临时分析结果目录管理
  分析结果会写入 `geoserver_data/temp_analysis`，并通过清理任务进行维护。

## 4. 当前界面中已预留但尚未完全实现的能力

右侧工具栏中展示了多个 GIS 工具入口，但目前真正接通后端执行链路的主要是：

- `10004` 缓冲区分析
- `20004` 坡度/坡向
- `20005` 等高线提取
- `20006` 山体阴影

其余如格式转换、要素简化、叠加分析、重采样、NDVI、自动出图、报表生成等，当前更多属于界面预留或后续扩展方向，暂未在现有代码中形成完整业务闭环。

另外，`坐标转换` 面板当前是占位实现，尚未接入真实分析逻辑。

## 5. 项目目录结构说明

```text
Shijian/
├─ vuePrj/        前端项目，负责页面交互、地图展示、图层管理、分析面板
└─ expreePrj/     后端项目，负责认证、数据上传、GeoServer 发布、分析任务调度
```

### 前端关键目录

- `src/views`
  包含登录页、工作台、个人中心、设置页等主页面。
- `src/components/workbench`
  包含左右侧边栏、数据拖拽上图、图层树管理等工作台核心组件。
- `src/components/toolsWidget`
  包含各类分析工具表单组件。
- `src/api`
  封装认证、用户、数据集、分析等接口请求。

### 后端关键目录

- `src/controllers`
  处理用户、认证、数据、分析相关接口逻辑。
- `src/routes`
  定义认证、用户、分析等路由。
- `src/models`
  定义用户和数据资产模型。
- `src/analysis`
  负责分析任务调度、DEM 转地形、Python 脚本调用。
- `src/analysis/python`
  存放缓冲区、坡度坡向、等高线、山体阴影、DEM 转地形等脚本。
- `src/middleware`
  包含鉴权、头像上传、数据上传等中间件。

## 6. 项目实现流程概括

整体业务流程可以概括为：

1. 用户注册并登录系统
2. 上传矢量或栅格空间数据
3. 在个人中心查看和管理自己的数据
4. 在工作台将数据拖拽到地图中
5. 后端自动将数据发布到 GeoServer
6. 前端通过 WMS 将图层加载到 Cesium 场景
7. 用户选择分析工具发起空间分析
8. 后端调用 Python 脚本生成分析结果
9. 分析结果再次发布为图层并回显到地图中

## 7. 总结

这是一个面向 GIS 数据管理与空间分析场景的三维可视化平台，已经完成了从用户体系、数据上传、GeoServer 发布、Cesium 展示，到部分空间分析工具闭环的一体化实现。

当前项目的亮点在于：

- 实现了前后端分离的 GIS 平台架构
- 打通了用户数据到地图服务发布的完整流程
- 将 Cesium、GeoServer、数据库与 Python 地理分析脚本整合到同一业务链路中
- 已具备继续扩展更多矢量分析、栅格分析与制图输出功能的基础
